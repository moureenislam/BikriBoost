# Local development

## Project layout

```text
BikriBoost.code-workspace       Open this in VS Code
BikriBoost.slnx                 Solution containing web app and tests
global.json                    Selects a stable .NET 10 SDK
.vscode/                       Build/test/run tasks and debugger configuration
scripts/                       SDK discovery and build/test helpers
Start-Demo.ps1                 Starts the local SQLite demo
BikriBoost.Web/
  Controllers/                 HTTP endpoints and MVC actions
  Models/Entities/             Database entities
  Models/Data/                 DbContext, seed data, and migrations
  Models/Services/             Marketing business logic
  ViewModels/                  Data passed to views
  Views/                       Razor pages and layouts
  Jobs/                        Background marketing worker
  wwwroot/                     CSS, JavaScript, images, and vendor libraries
  Properties/launchSettings.json
  appsettings*.json            Application and development configuration
  App_Data/                    Local database and uploads (created at runtime)
BikriBoost.Tests/
  Unit/                        Business rule tests
  Integration/                 HTTP and database workflow tests
docs/                          Setup and feature walkthrough
```

`bin/` and `obj/` are generated by .NET. `.tools/` contains local tooling and
`artifacts/` contains generated reports. These are not application source.
The existing source, including uncommitted changes, remains in its original folders.

## Commands and debugging

Open the workspace, then use **Terminal > Run Task** to select restore, build,
test, or run demo. **Ctrl+Shift+B** builds the solution. **F5** starts the
`BikriBoost: local demo` debugger and opens the browser once the app is ready.
Breakpoints work in C# with the Microsoft C# extension installed.

The task scripts search for an installed .NET 10 SDK, then check
`%LOCALAPPDATA%\BikriBoost\dotnet\dotnet.exe`. On this machine, VS Code is also
configured to use that local SDK. On another machine, install the
[.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) and update the
SDK paths in `.vscode/settings.json` and `.vscode/launch.json` if necessary. Initial package restore
and C# debugger setup require internet access.

For a different HTTP port:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start-Demo.ps1 -Port 5072
```

Then open <http://localhost:5072>. Run only one app instance per demo database.
If port 5071 is occupied, stop your previous run or use a different port.

## Demo data and tests

Development mode uses `BikriBoost.Web/App_Data/marketing-demo.db` and seeds sample
records automatically. Sign in as `owner@demo.bikriboost.test` or
`marketer@demo.bikriboost.test` with `Demo@12345`. The feature walkthrough explains
the roles and workflows. Publishing to social media is simulated.

Automated tests use isolated in-memory SQLite databases. Running tests does not
reset your saved demo database. Database files and uploaded files in `App_Data`
are ignored by Git; keep a separate backup if you want to preserve demo changes.

The optional MariaDB configuration and migration instructions are in the README.
They are separate from the default SQLite demo and are not required for local testing.
